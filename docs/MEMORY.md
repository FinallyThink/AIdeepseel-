# 本地长期记忆

普通回复仍参考最近 10 轮，选评参考最近 6 轮。在此基础上，新版会检索本地长期记忆，并附到 AI 请求中。每次附加记忆默认最多 6000 字，可在管理端调为 1000～16000 字；这是字符额度，不是模型 token 窗口。检索使用房间标识、用户标识和关键词，优先相关对话并参考最近摘要，不是把全部历史送给模型。

## 本地目录

正式文档固定保存在当前项目 `memory/`：

- `knowledge.md`：主播手工记忆。可在管理端编辑或直接用文本编辑器修改，不会被 AI 覆盖。
- `sessions/<启动时间>-<编号>.md`：每次启动的可读聊天档案。只记录已完成的真实播报，包含房间、观众、原消息、澜鲸回复和时间。
- `sessions/<启动时间>-<编号>.jsonl`：对应结构化原始记录，用于去重、恢复与检索。按追加方式保留，不以最近 60 轮为上限。
- `summaries/<房间摘要编号>.md`：AI 生成的往期直播摘要。
- `summary-state.json`：每个房间已归纳到哪里，用于增量整理，避免漏掉整理过程中新增的消息。

启动时可将旧版保留的真实历史快照补充归档，并明确标记“已开始播报，未核实播放结束”；离线演练房间和演练模式不写入正式记忆。自检使用隔离目录 `.smoke-profile/memory/`。

## 自动整理与后续引用

每个房间新增 20 条未归纳的记录后，后台使用已配置的 DeepSeek 生成增量摘要，并保留旧摘要中的重要事项。每次最多处理 20 条；至少间隔一分钟继续下一批。失败时保留旧摘要和原始档案，可重试，不影响礼物队列和正常播报。管理端“立即整理摘要”可处理不足 20 条的新记录。

选评和回复会读取手工笔记，再按同 RoomId 或 WebRoomId 检索旧对话和摘要。相同 WebRoomId 可跨开播场次继续回忆；只提供会变化的 RoomId 且采集器没有稳定标识时，旧场次记忆无法可靠自动关联。手工笔记是主播全局设定，其余自动记忆按房间隔离。

摘要和观众历史都是数据引用，不作为系统指令。提示词要求区分来源，不凭相同昵称断言身份，不把未核实的观众陈述当事实。记忆是辅助信息，不保证每次都引用到全部历史细节。

## 管理与保留

管理端“长期记忆”可开关记忆引用与自动整理、调整注入额度、查看最近档案和摘要、打开本地目录。关闭长期记忆会停止 AI 引用和自动整理，原始聊天仍持续归档；现有文档不会删除。

本地 Markdown 文档长期保留，不自动清理。档案 Markdown 由 JSONL 重建，请把需要修改的长期设定写到 knowledge.md，避免手改自动生成档案。可备份整个 memory 目录。未播出的队列消息不写入记忆，不存储音频和 API 密钥。文档保存在本地；选中的记忆片段会随正常回复请求发送给已配置的 AI，自动整理摘要也会调用该 AI。
